# Lessons

- 2026-10-25: For large multi-part requests, this user wants a written master plan and a multi-agent cost-routing framework BEFORE any execution (even read-only exploration was interrupted). Plan first, delegate scans to cheap agents, keep design and client-facing copy at the manager level.
- 2026-10-25: Never trust project titles in `projectsData.ts`. A visual check found mislabels (0115 "house" is a restaurant). Verify categories from the images.
- 2026-10-25: Concept v1 (static dark page, sheet frames, subtle wireframe) was rejected as "dry, like a PDF, no life". This user wants visible motion that shows the portfolio's strength: a cinematic hero, scroll-driven storytelling, a horizontal gallery, cursor and magnetic interactions. Load premium-web-design, interactive-portfolio and ui-ux-pro-max before any design work. Use Opus for design and cheaper models for pipeline work.
- 2026-10-25: The v2 motion concept was rejected for heavy dark colours, an inconsistent type scale and mixed image sizes. The user wants it built on the existing site's identity (light paper, navy, Fraunces/Plex). Rules from this:
  - Use one type scale and one image ratio (4:3).
  - The user's project total (200+) is authoritative. Never replace it with the site count.
  - Interiors are counted per space.
  - Kindergartens: 2 (0195, 0196), and 0196 has two facade options.
- Earlier: The editorial-minimal concept was rejected as "ordinary". Concepts must feel high-end and capability-led (BIM, execution), not a plain template.
